| Claim | Manual assessment and important boundary |
| --- | --- |
| C01 — finite rounding | [RoundingContract.lean](tensor-core/TensorCore/Theory/Binary/RoundingContract.lean) connects all four modes to finite-value ordering/minimum-distance predicates. `roundBinary_isSome_iff` requires a well-formed format and an exact rational within maximum finite magnitude. Rejection outside that interval is intentional, including directed modes. |
| C02 — encoding and zero | [SignedBijection.lean](tensor-core/TensorCore/Theory/Binary/SignedBijection.lean) carries the zero sign separately and supplies both inverse laws. Numerical rounding predicates alone do not distinguish the two zeros; `roundBinary_zero` and `roundBinary_sign` supply the arithmetic convention. |
| C03 — FP64 fused arithmetic | [Invocation.lean](tensor-core/TensorCore/Semantics/Invocation.lean) constructs the fused value from decoded original operands. The success theorem requires one product, successful preparation, and an in-range fused result; it does not require the intermediate product to fit FP64. This is scalar fused arithmetic, not an FP64 matrix-equivalence result. |
| C04 — tensor-core semantics | [Definition.lean](tensor-core/TensorCore/PaperSpec/Definition.lean) independently defines raw exponents, zero exclusion from exponent selection, alignment floors, sign-restored magnitude truncation, and final finite FP32 rounding. [Supported.lean](tensor-core/TensorCore/PaperSpec/Supported.lean) connects all eight selected paths, including rejection. Fixed-width equality separately requires the stated carry capacity. |
| C05 — error, recovery, order | [ErrorBounds.lean](tensor-core/TensorCore/Theory/ErrorBounds.lean) includes final conversion loss. [Composition.lean](tensor-core/TensorCore/Programs/Composition.lean) telescopes residuals through encoded accumulators. The nonmonotonicity theorem retains its factor-realizability, scale, floor, count, and perturbation-range premises; it is not a universal threshold for every input. |
| C06 — bounded EFT | [BoundedEFT.lean](tensor-core/TensorCore/Programs/BoundedEFT.lean) uses bounded-word extraction and consolidation. [Correctness.lean](tensor-core/TensorCore/Theory/EFMachine/Correctness.lean) derives preparation/capacity and the directly rounded original ideal from finite inputs and any finite supplied D. It does not assume D is a correct tensor-core result. The 576-bit type is an arithmetic capacity guarantee, not a verified optimized nine-limb GPU implementation. |
| C07 — extraction and Eq.20 | [ExtractionGrid.lean](tensor-core/TensorCore/Programs/ExtractionGrid.lean) permits grids at least as coarse as alignment. The low-part reconstruction and signed overlap are consistent. Exact scalar summation retains the minimum grid, strict coefficient budget, and finite magnitude premises; scalar correction additionally checks D, overlap, and retained-sum representability. The equation-number correspondence to the corrected manuscript was not independently reconfirmed in this review. |
| C08 — composition | [Invocation.lean](tensor-core/TensorCore/Theory/Invocation.lean) recovers the original-input ideal using the full stage residual. [Loops.lean](tensor-core/TensorCore/Theory/ProgramBounds/Loops.lean) derives repeated-program accuracy from operand scale, initial magnitude, total count, and headroom; it does not assume the body restores its initial state. Adaptive branching remains outside the contract. |
| C09 — raw FP16 GEMM | [Matrix.lean](tensor-core/TensorCore/PaperSpec/Matrix.lean) specifies increasing row/column reductions, complete 16-product instructions, ordered internal groups, tail zero padding, and logical output cropping. [GemmEquivalence.lean](tensor-core/TensorCore/PaperSpec/GemmEquivalence.lean) observes every group output and failure without a successful-run premise. Empty K explicitly checks and preserves finite C, including -0. |
| C10 — native BF16/TF32 GEMM | [NativeGemm.lean](tensor-core/TensorCore/Programs/NativeGemm.lean) separates packed BF16 and 19-bit TF32 and uses five schedules. [NativeGemmEquivalence.lean](tensor-core/TensorCore/PaperSpec/NativeGemmEquivalence.lean) checks the parameters against the separate profile table. The scaled pipeline and [NativeConvertedAnalysis.lean](tensor-core/TensorCore/Programs/NativeConvertedAnalysis.lean) include source conversion, every scalar stage, successful execution, and source-relative error. |
| C11 — complete scaled FP16 GEMM | [ScaledGemm.lean](tensor-core/TensorCore/Programs/ScaledGemm.lean) starts AB at +0, separately rounds alpha times the product and beta times C, then adds and converts the output. [ScaledGemmEquivalence.lean](tensor-core/TensorCore/PaperSpec/ScaledGemmEquivalence.lean) covers these observations and rejection. Alpha/beta equal to zero do not bypass operand validation or intermediate execution. |
| C12 — input-derived certificates | [GemmAnalysis.lean](tensor-core/TensorCore/Programs/GemmAnalysis.lean) requires existing results and defined ideals in `GemmAccurate`. [ConvertedGemmAnalysis.lean](tensor-core/TensorCore/Programs/ConvertedGemmAnalysis.lean) references the original source matrices and adds conversion loss multiplied by `abs(alpha)`. Matrix bounds use the sum of absolute entries, not the induced matrix 1-norm. Inference uses unsigned magnitude bounds and can refuse cancellation-heavy but accurate computations. |
| C13 — tighter bounds | [GemmTightInputBounds.lean](tensor-core/TensorCore/Programs/GemmTightInputBounds.lean) bounds product perturbation using two valid expansions and takes their minimum; converted magnitudes preserve the interaction between both input errors. [ExactScalarAnalysis.lean](tensor-core/TensorCore/Programs/ExactScalarAnalysis.lean) justifies exact multiplication by ±1 and addition with a zero-magnitude operand under finite-value premises. |
| C14 — quantified families | [GemmFamily.lean](tensor-core/TensorCore/Programs/GemmFamily.lean) and [EntryFamily.lean](tensor-core/TensorCore/Programs/EntryFamily.lean) quantify over all matrices satisfying finite decoding and magnitude caps. The per-entry checker uses each A row's maximum and each B column's maximum. Nonempty, distinct, nonzero members are established by the review regressions. Empty output dimensions remain vacuous; arbitrary negative Lean caps can define empty families, while the CLI rejects them. |
| C15 — certified decisions | [GemmSelection.lean](tensor-core/TensorCore/Programs/GemmSelection.lean) fixes the workload before varying candidates and derives accuracy from a successful input check. [CostSelection.lean](tensor-core/TensorCore/Programs/CostSelection.lean) minimizes supplied rational cost among analyzer-certified candidates only. Refusal does not prove inaccuracy, and supplied cost is not measured GPU performance. The Python renderers preserve workload, precision, candidate order, costs, tolerance, and the selected decision. |
| C16 — CUTLASS connection | [CutlassWmma.lean](tensor-core/TensorCore/Kernels/CutlassWmma.lean) matches the inspected pinned fixture's zero accumulator, CTA/warp coordinates, increasing K tiles, and identity epilogue. Pinned headers confirm the residue-first iterator, supporting the restriction to K divisible by 16. This is a manually transcribed arithmetic projection; C++ memory behavior, CUDA compilation, and GPU execution are separate obligations. |
